-- Library API root set for the kimchi package.
--
-- The curated top-level surface the library exists to provide. Lean has no export-list
-- mechanism (everything non-`private` is visible once imported), so this manifest — not the
-- type system — defines the public API. It is the root set for dead-code analysis:
--
--   a declaration in `Kimchi.*` is LIVE iff it is in the transitive constant-dependency
--   closure of these roots; anything compiled but outside that closure is dead.
--
-- The list is a MINIMAL GENERATING SET: a result reachable from a listed root is deliberately
-- not listed (e.g. `Kimchi.Protocol.sound` and the openings seam
-- `kimchiProof_sound_of_openings` are live through every run-level root; `zH_dvd_iff` and
-- `dvd_separation` through the whole soundness line). `scripts/check_axioms.lean` separately
-- pins the existence and axiom closure of the headline theorems, including ones unlisted here.
--
-- Format: one fully-qualified declaration name per line; `--` lines and blanks are ignored.
--
-- Note: the `kimchi-demo` executable (Main.lean) is a SEPARATE build root, reaching the demo
-- defs `Kimchi.Gate.{egQ, egGood, egBad, satisfies}`. Those are demo-only and are not part
-- of this library API surface, so they are reachable through the executable rather than here.

-- THE KNOWLEDGE-SOUNDNESS DEVELOPMENT
--
-- The deployed verifier is knowledge-sound, per curve, in the random-oracle model: over a
-- uniformly sampled setup basis and a uniform challenge table, and for every complete fork
-- tape, the probability that the executable verifier accepts while the forking extractor
-- returns no table satisfying the circuit the verifying key corresponds to is at most
--   (Q + k + 1)*3/2^128 + (2^k + 1)*eps + delta + (Q + 1)*szBudget/2^128.
-- Trust surface: the standard axioms plus the Pasta certificates. No Fiat-Shamir axiom.
Kimchi.Verifier.KnowledgeSoundness.vesta_kimchi_knowledge_sound
Kimchi.Verifier.KnowledgeSoundness.pallas_kimchi_knowledge_sound

-- Faithfulness: the deployed verifier IS the challenge-generic one at the sponge's own
-- squeezes, stated at named sources rather than as an existential (an existential over the
-- challenges is satisfied even by a verifier with Fiat-Shamir deleted).
Kimchi.Verifier.KnowledgeSoundness.kimchiVerify_eq_verifyWith

--
-- These are the results behind "no grid is needed": per-commitment representations plus ONE
-- accepted opening give every per-row evaluation pin, against two counted exclusion sets.
-- The endpoints do not call them -- they call the split forms

-- un-batching argument is the part of this development with no counterpart upstream
-- (ironwood's `batch_open_soundV` needs a grid it cannot obtain from one run). Rooting is a
-- holding action: decide whether they earn standalone status or should follow the chain out.
--
-- NOTE: marking these `private` was considered and does not compose with rooting -- private
-- names are mangled, and nothing in their own files consumes them, so they would read as
-- unused file-local declarations to both `lake lint` and the dead-code pass.
