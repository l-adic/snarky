-- Library API root set for the kimchi package.
--
-- The curated top-level surface the library exists to provide. Lean has no export-list
-- mechanism (everything non-`private` is visible once imported), so this manifest — not the
-- type system — defines the public API. It is the root set for dead-code analysis:
--
--   a declaration in `Kimchi.*` is LIVE iff it is in the transitive constant-dependency
--   closure of these roots; anything compiled but outside that closure is dead.
--
-- The list is a MINIMAL GENERATING SET: a result reachable from a listed root is deliberately
-- not listed (e.g. `zH_dvd_iff` is live through `Lift.Argument.bridge`, and each gate's
-- `Argument` family through `Protocol.Linearization`'s `gateLinearization`).
-- `scripts/check_axioms.lean` separately pins the existence and axiom closure of the headline
-- theorems, including ones unlisted here.
--
-- NOTE on what this package now is. `Kimchi.Verifier.kimchiVerify` is a SPECIFICATION — the
-- transcription of proof-systems' `kimchi/src/verifier.rs`, and the anchor a circuit
-- implementation is proved faithful to — not a theorem-bearing object. The probabilistic
-- soundness development that once sat above it (`Verifier/KnowledgeSoundness.lean`,
-- `Verifier/Capstone/`, `Verifier/Forking/`, `Verifier/Reduction/`) was retired; see git log
-- for the tree. Nothing here should be read as a soundness claim about the deployed verifier.
--
-- Format: one fully-qualified declaration name per line; `--` lines and blanks are ignored.
--
-- Note: the `kimchi-demo` executable (Main.lean) is a SEPARATE build root; it and the
-- inline `#eval`/`example` regression demos consume the `eg*` defs rooted at the end of
-- this file — those consumers are invisible to the constant walk, so the defs are rooted
-- explicitly.

-- THE ARITHMETIZATION — what the verifier's commitments commit to.
--
-- The verifier opens commitments; it never handles raw polynomials. This layer is the other
-- side of that: how a constraint system becomes the polynomial family the commitments are
-- taken over, and what divisibility of that family means about the circuit.
--
-- `satisfies_iff_fullFamily_dvd` is the headline and the only result in the tree linking
-- `Index.Satisfies` (the circuit) to the committed polynomials: a witness table satisfies the
-- index iff, at every nondegenerate challenge pair, some accumulator makes every member of
-- the family divisible by `Z_H`. Its engine — `zH_dvd_iff`, `dvd_separation`, the `Argument`
-- lifts, `gateMember`, `fullFamily`, `pubPoly` — is live through it.
--
-- NOTE on `dvd_separation` and the SZ layer: the bad sets are EXPLICIT FINITE SETS with
-- proved cardinality bounds, and the statements quantify over challenges outside them. That
-- is deterministic algebra (a Vandermonde / too-many-roots argument), not a probabilistic
-- claim. It is unrelated to the retired knowledge-soundness development, which is what the
-- probabilistic reading belonged to; see docs/soundness-line-retirement.md.
Kimchi.Index.satisfies_iff_fullFamily_dvd

-- The same arithmetization at an EVALUATION check rather than a divisibility one: one
-- accepting check of the aggregate against `t·Z_H`, at an α outside `badAlphas` and a ζ
-- outside `badZetas`, implies the witness satisfies the index. This is what makes "verify at
-- a single point" legitimate, and it is what the Schwartz–Zippel layer
-- (`SchwartzZippel.lean`, `Aggregate.lean`) exists to support: both bad sets are explicit and
-- carry proved cardinality bounds, so the statement quantifies over good challenges rather
-- than over a distribution. The QUANTITATIVE side of the ζ bound needed the degree accounting
-- of the former `Index/Degree.lean`, which went with the ideal-protocol layer; what is kept
-- here is the qualitative theorem.
Kimchi.Index.satisfies_of_evalCheck

-- The bad sets' cardinality bounds, rooted as the anti-vacuity companions of the entry
-- above: `α ∉ badAlphas` says nothing if `badAlphas` could be the whole field. These pin the
-- α bad set at `≤ n·(K−1)` and the ζ bad set at `≤ D`, which is what makes the exclusion a
-- genuine restriction and gives the counting its probabilistic *reading* — which is a remark
-- about the statements, never part of one.

Kimchi.card_badZetas_le
Kimchi.SZ.card_badComb_le
